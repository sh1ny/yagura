## DayZ end to end, in process (task 10.2)

Written 2026-10-20 by the agent (agent). `apps/yagurad/test/mods/dayz_mods_end_to_end_test.dart` runs the shipped `plugins/dayz` (task 10.1) in the daemon with the fake SteamCMD, the fake Steam Web API and the fake process host. No real Steam account, DayZ server or BattlEye is involved, so it shows the daemon's side of the work, not what the real game does with it. It runs on every platform and needs no administrator rights.

- `twelve_mods_to_a_launched_server_in_one_start`: an instance linked to a Steam account is installed (app 223350), 12 workshop items (app 221100, two roles) are set, and one `Start` downloads them, links each as `server/@<title>` into the content store, copies each `.bikey` into `server/keys/`, binds `server/yagura/serverDZ.cfg` and `server/yagura/battleye/BEServer_x64.cfg` from the plugin's templates (including two secrets, which stay out of the launch arguments), and launches with `-config`, `-BEpath`, `-profiles`, `-port`, `-steamQueryPort`, `-mod=` and `-serverMod=` in load order. The server counts as started when its RPT shows the ready line.
- `a_second_instance_shares_one_content_directory`: a second instance with the same 12 mod versions downloads nothing, and each of its links resolves to the same version directory as the first instance's. The store holds one directory per item.
- `a_mod_update_re_links_only_the_changed_mod`: one of the 12 items is updated on the workshop. The update check flags only it, `UpdateMods` downloads only it and re-links only it, the other 11 links keep their targets, and the next `Start` launches with the same arguments.
