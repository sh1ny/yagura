## Running the user criteria (5-7)

From the repository root on a Windows machine, with mise set up:

1. Prepare a data directory with the Valheim plugin:

   ```sh
   mkdir F:/yagura-m1/data/plugins
   cp -r plugins/valheim F:/yagura-m1/data/plugins/
   ```

   (These and the commands below are one per line and work in Nushell, PowerShell and bash; `mkdir` creates the parent directories in Nushell and PowerShell, use `mkdir -p` in bash.)

2. Build the daemon. The server is started through `yagurad`'s own `launch`, `relay` and `signal` modes, so it must be the compiled `yagurad.exe` (under `dart run` the executable is `dart.exe` and Start fails):

   ```sh
   cd apps/yagurad
   mise exec -- dart build cli -t bin/yagurad.dart -o F:/yagura-m1/build
   ```

   Terminal A, start it (leave it running):

   ```sh
   F:/yagura-m1/build/bundle/bin/yagurad.exe run --console --dev --data-dir F:/yagura-m1/data
   ```

   It prints `DEV MODE: unauthenticated, localhost only` and listens on `127.0.0.1:7443`.

3. Terminal B, start the desktop client:

   ```sh
   cd apps/yagura_desktop
   mise exec -- flutter run -d windows
   ```

4. Criterion 5: create a Valheim instance, Install (about 2.1 GB through SteamCMD, anonymous), then Start. Pass when the instance reaches `running` (the log-match health check sees `Game server connected`) and the log view shows the server's lines.

5. Criterion 7 (while it runs): note the server PID (`tasklist | findstr valheim_server`), kill the daemon by closing terminal A's window (not `taskkill /IM yagurad.exe`: the relay is a `yagurad.exe` too, in its own console, and must keep running), open a new terminal and start the daemon again with the same command. Pass when `valheim_server.exe` keeps the same PID and the client shows the instance `running` again after it reconnects.

6. Criterion 6: note the newest world save under `F:/yagura-m1/data/instances/<id>/save/worlds_local/<world>/` (`_main.<N>.db2`, where a higher `<N>` is a newer save generation), then Stop from the client. Pass when the stop reports `stopped_by: graceful` and the world file's time stamp is newer than the stop request and not later than the server's exit.
